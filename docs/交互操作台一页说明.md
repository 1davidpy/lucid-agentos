# lucid-agentos 交互操作台｜一页式介绍

**当前入口：** http://192.168.2.189:8787/（内部局域网访问）

## 一句话定位

交互操作台是 lucid-agentos 的“任务指挥与证据窗口”：操作者可以用自然语言给机器人下达任务，同时查看机器人看到了什么、如何行动、环境如何变化，以及系统为什么判断任务成功、失败或需要停止。

## 页面四个区域怎么看

1. **仿真执行画面**：第三人称画面帮助现场人员观察整体过程；机器人第一视角代表智能体实际可用的视觉来源。第三人称仅供操作者查看，不作为智能体的隐藏信息。
2. **语言代理**：输入“去厨房取水并返回”等自然语言任务，系统会根据当前观测调用允许的机器人能力。这里展示的是任务目标和执行反馈，不是预先录制的固定动画。
3. **实时建图与空间态势**：地图、机器人位姿、最近障碍和运动速度来自本轮在线传感器，用于理解机器人对环境的实时认识，而不是直接读取场景答案。
4. **工具链调用记录**：时间线记录模型轮次、工具调用、观测、系统事件、执行状态和失败原因，方便复盘“系统做了什么、依据是什么”。

顶部状态区用于查看仿真、工具连接、导航和智能体是否就绪；“急停”用于立即中止运动，“复位实验”用于停车后清空本轮地图、轨迹和空间记忆，并重新建立干净的实验环境。

## 3 分钟推荐演示流程

1. 先介绍双视角：左侧是现场人员的全局观察，右侧是机器人自己的第一视角。
2. 确认 SIM、MCP、NAV 和 AGENT 状态正常，再输入一条清晰任务，例如“去厨房取水并返回”。
3. 请观众同时关注第一视角、实时地图和工具调用时间线，说明机器人正在基于新观测逐步执行，而非播放脚本。
4. 任务结束后重点讲结果证据：命令成功不等于任务完成；系统还会检查是否到达、是否停稳，以及新的传感器画面是否满足目标条件。
5. 最后展示急停或实验复位入口，说明系统把安全退出和可重复实验作为完整流程的一部分。

## 60 秒推荐讲解词

> 这是 lucid-agentos 的交互操作台。我们可以直接用自然语言向机器人描述任务，并同时看到它的第一视角、实时地图、运动状态和完整执行记录。操作台的价值不只是“让机器人动起来”，而是把整个过程变得可观察、可解释、可复盘。系统会区分工具是否成功调用、规划器是否到达、机器人是否真正停稳，以及最终是否有新的现场证据证明任务完成。如果风险过高、传感器信息不足或验证不通过，系统会停车并给出不完整结果，而不是勉强宣称成功。对研发团队，它是调试和评测工具；对业务和合作伙伴，它是理解具身智能如何工作的直观窗口。

## 对外表述边界

- 当前页面主要是 **G1 仿真操作台**；除非展示素材明确来自实机，否则不要称为“真实机器人现场运行”。
- 操作台是内部局域网服务，不是面向公众长期开放的云端产品入口；外部传播建议使用录屏、现场演示或审核后的截图。
- “工具调用成功”只说明系统完成了一次调用，不代表用户任务已经完成；完成结论必须以到达、停稳和新观测验证为准。
- 第三人称画面供操作者观察，不会作为智能体决策信息；不要将其描述为机器人“看到”的内容。
- 急停、安全回撤和风险检查降低实验风险，但不等同于生产环境的绝对安全认证。

## 常见问题

**操作台是遥控器吗？** 不只是。操作者给出目标，智能体自主选择受限技能并执行；操作台同时承担状态观察、过程记录、安全控制和结果复盘。

**为什么要展示失败或“不完整”？** 在真实环境中，证据不足时拒绝宣称成功，比给出一个看似漂亮但无法验证的结果更可靠。失败原因可见，也能帮助团队持续改进。

**为什么同时显示两个视角？** 第一视角用于说明机器人依据什么进行判断；第三人称帮助现场人员理解整体动作，两者的信息边界明确分开。
